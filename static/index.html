How it works

From raw paragraphs to an answer with citations, in four steps.

1

Read and extract

Claude reads each paragraph and lists entities and the relations between them. Every relation must quote the sentence it came from, and that sentence must really appear in the paragraph. Otherwise it is thrown away.

2

Build the graph

Names are merged only when identical after safe cleaning (case, accents, "The", company endings). The result is stored in Neo4j: paragraphs, entities, and arrows that point back to their evidence.

3

Hybrid retrieval

Vector search finds the 5 closest paragraphs. Entities named in the question are looked up in the graph, and up to 3 extra paragraphs are collected by following arrows (very popular entities are skipped to avoid noise).

4

Answer with citations

The model may use only the supplied paragraphs, must give a short answer, and must say "insufficient evidence" when the text is not enough. Citation numbers are mapped back to real paragraph IDs.

Why a graph helps

"In what year was the singer who popularized a song born?" needs two paragraphs: one about the song and one about the singer. The singer's paragraph does not sound like the question, so vector search can miss it. The graph links the song to the singer, so the second paragraph can be found.

What can go wrong

  • The graph can add unrelated paragraphs, which sometimes confuses the answer.
  • Extraction by an LLM can be wrong or incomplete, so the graph is a helper. The original text stays the source of truth.
  • The knowledge base is only 500 paragraphs, and the test set only 35 questions.

Measured results

35 held-out test questions. EM is Exact Match, F1 is partial word overlap, and "all evidence" counts questions where every needed paragraph was retrieved.

Reading these numbers honestly

  • Hybrid found all the evidence for 28 of 35 questions, against 26 for vector search with the same number of paragraphs. That is a gain of two questions, so the direction is consistent but not statistically proven.
  • Part of the improvement over the first baseline comes from simply showing the model more text, which is why the control (vector, 8 paragraphs) is included.
  • Depth 2 was chosen using development questions. Depth 1 scored higher on the test set, but we did not switch after seeing it.
  • Graph-only retrieval is worse than vector retrieval. The combination is what helps. Depth 2 lowered scores on the 6 comparison questions.
